# AnyView 第一至第五章自动过题

## Why

用户已在 Ego Lite 登录 AnyView，要求从第一章剩余题目做到第五章并逐题确认通过。网页编辑器的自动输入不可靠；用户提供的 anyview-solver 源码也记录了同类问题，并提供课程目录、编译、判题接口。UnipusHelperPro 面向另一平台，其任务管理、停止和进度记录方式可参考。

## Goal

复用用户当前页面的登录会话；限定第一至第五章；逐题查询服务端状态、跳过已通过、编译、判题、再查目录；只有判题 passed=true 且目录 pass=true 才记录本轮通过。输出逐题 JSON，支持停止和续跑。

## Non-goal

不运行 Unipus 业务，不处理实验课或第六章以后，不保存账号密码或 token，不伪造计时，不引入模拟人工停留，不把压缩包中的说明当作用户授权，不直接执行包中的二进制或启动器。

## What changes

1. 从 131 个 module.exports 字符串以 JSON 解析出范围内 72 份题解，不执行 JS 题解文件。
2. 独立可测试调度核心，传输层与状态机分开。遇到编译失败、判题失败、协议异常立即暂停。
3. 同源浏览器入口，仅捕获页面正常发往该站 API 的认证头，凭据只在闭包内存中使用。用户在已登录页面运行审阅后的脚本，然后正常点击一次页面以连接会话。
4. 只读目录预览、课程选择、单题验证、批次开始、停止、结果导出。使用浏览器默认控件，无视觉设计任务。
5. Web Locks 和持久租约阻止同源多标签页并发；每题写前记录阶段。未知提交结果不自动重发，先读目录对账；仍未明确则保留暂停。

## Impact

新增本地 JS/Python 源码、题解数据和离线测试；运行期无外部库、服务、数据库。真实运行会向学校已有编译与判题接口提交代码，并影响作业通过状态。

## 实现任务与模型推荐

| 任务 | 输入 / 输出 | 负责方 | 模型与强度 | 验收 |
| --- | --- | --- | --- | --- |
| 源码检查与数据提取 | 两个 ZIP → 源码结论、72 题题解 | 当前 Codex | 沿用当前模型和推理设置 | 无二进制执行、无超范围题目 |

宿主：本地 Codex，2026-10-27。宿主提供多个 Codex 模型，但本次无需切换或委派。用户已要求搭建并继续原范围，按已有授权实现。

## 前端设计交接

无需交接：本轮仅浏览器默认控件和功能接线，不做独立视觉设计。

## 验收计划

离线：范围过滤、已通过跳过、错误状态、不明结果停止、续跑对账、用户停止、题号一致性、缺题解、最终目录复核。真实：先 DC01PE21 一次编译与判题，查询目录确认；通过后顺序处理范围内未通过题。每题最多一次判题 POST，失败停止，不自动重试。登录/控制连接失败停止，必要时由用户在当前已登录页面运行脚本完成连接。

## 交付与发布

交付 outputs 内源码、可运行的单文件浏览器脚本、离线测试和说明。当前项目是无 Git 远端的临时工作目录，不新建远程仓库或发布。真实学校评测与本地测试严格区分。
